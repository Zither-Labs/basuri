# Coding Preferences

## Git & publishing (hard rule)

- **Never push to git unless the user explicitly asks.** Do not run `git push`, do not
  publish/deploy, and do not trigger anything that updates the remote or the live site
  on your own initiative. Local edits, and even local `git add`/`commit`, may be fine
  when needed, but **publishing (push) requires an explicit request every time**.
- If a change is ready to go live, stop and ask first; wait for a clear "push it".

## Repository consistency (always)

- **Keep the whole repo consistent.** When a change is made to one file, apply the
  equivalent change to every other file that shares that content. Never let files
  drift out of sync.
- Interactive HTML and Markdown twins must stay in sync (`foundations.html` ↔
  `foundations.md`, and the same for chords, strumming, songs, kids, quest, etc.).

## Scope

Follow the workspace locked scope in `../howto/guitar-scope.md`. **v1** is the
spine; **v2** pages (scales, modes, CAGED, jazz lite, tunings, ear, improv,
fingerstyle, reading) are opened deepeners; Break rut is an Exercises loop lab —
  keep Kids free of jazz/barre depth.
Pedagogy: agent proposes, user approves; two-source check (Berklee, classical
methods, Hal Leonard).

## General

- Prefer editing existing files over creating new ones.
